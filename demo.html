partition-bench

A schedule explorer for distributed partition assignment. It searches interleavings of lock acquisition, membership callbacks, disconnects and session expiry, checks that no partition ever has two owners, and shrinks every failure to a trace short enough to read.

12,000 schedules run 6 implementations compared Pure Python, no dependencies Built on work in kazoo's SetPartitioner

    Which guards carry the weight

    naive · 2-step safety bug

    Tentative locks must belong to one attempt

    With a shared lock list, a stale attempt that returns late from a blocking acquire rolls back the newer attempt's locks. The newer attempt then processes partitions it no longer holds.

    no wait check · 52% deadlock

    Waiting attempts must notice they are stale

    An attempt planned from an old membership snapshot waits forever on a partition that now belongs to someone else, while holding locks the current attempt needs.

    no connection checks · 0.8% of runs

    The commit must check the session

    A worker whose session expired can still publish ownership. Random testing hits this in under 1% of runs, and the shrinker turns it into a 13-step trace.

    two ablations · 0 failures

    Some guards are redundant here

    Fencing on disconnect and checking queued notifications never mattered once the commit checks connectivity atomically. In the real client they still matter, because commit and connection state are not atomic without an added lock.

    How it works

    A model you can search

    • Coordinator. Membership as sessions, locks owned by a session and lock object. An expired session loses its locks.
    • Workers. Each allocation attempt is a generator. Every yield is a point where another step can run.
    • Receipt and delivery. A membership change is received before its callback runs. Most of the races live in that gap.
    • Shrinking. A schedule is a list of choices. The shrinker deletes and lowers choices while the same kind of failure still happens.
